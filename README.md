# サッとレシート (satto-receipt)

ローカル暗号化のレシート記録PWAです。GitHub Pages に静的配信してもレシートデータは端末内（IndexedDB + AES-GCM）に保存されます。店名・日付・合計を読み取り、CSVでバックアップ/復元も可能です。

## 主な機能
- ブラウザ内OCR（Tesseract.js）で店名/日付/合計を自動抽出
- 任意の Gemini 読み取り。標準は Gemini 3.5 Flash-Lite で、3.8 Flash に切り替えられます。ONのときだけレシート画像を Google の API に送ります。月次のふりかえりは店名と金額の集計だけを送ります。APIキーは端末内に保存します
- 端末内暗号化保存（パスフレーズ復号）。暗号文とソルトは IndexedDB にあります
- 店名・日付・合計金額が一致するレシートは保存前に重複確認。店名の全角/半角や空白の違いも吸収し、別の買い物なら確認して保存できます
- 画像保存はデフォルトOFF。必要時のみ圧縮保存（長辺1280px / JPEG 0.6）＋画像クリーンアップボタン
- カメラ撮影 or 画像アップロードから読み取り。Gemini をOFFにするとオフラインの Tesseract を使います
- CSVエクスポート/インポートでバックアップ・復旧
- 月別の合計、飲み会/自腹、レスポンシブ対応（狭い画面は1カラム + 下部アクションバー）

## 開発・実行
```bash
npm install
npm run dev   # 開発サーバー http://localhost:5173
npm run build # 本番ビルド
```

## デプロイ（GitHub Pages の場合）
- `vite.config.ts` の `base` と `manifest.start_url` を `/satto-receipt/` に設定済みです。リポジトリ名が異なる場合は書き換えてください。
- `npm run build` 後、`dist/` を Pages に公開してください。
- `main` へのマージ後は `Deploy to GitHub Pages` がテスト・ビルド・公開を行います。Pages の公開元設定は変更しません。
- 公開元がブランチの場合、GitHub 自動の `pages build and deployment`（Jekyll）が同じコミットを公開し終わるまで待ち、その後に Vite の `dist/` を公開します。固定秒数の待機ではなく、実行状態を確認して公開の上書きを防ぎます。公開元が GitHub Actions の場合は待機せず公開します。
- 待機は最大15分です。タイムアウトした場合は自動Pages処理の完了後に `Deploy to GitHub Pages` の失敗したジョブを再実行してください。新しい `main` の更新が入った場合、古いビルドの公開はスキップします。
- スマホに以前の表示が残る場合は、公開完了後にアプリ内の「アプリ更新」を押してください。保存済みレシートを消す初期化は不要です。

## 使い方
1. 初回にパスフレーズを設定（復号に必須。レシート本文はサーバーに送信されません）。「次回から入力を省略」をONにすると、パスフレーズがこのブラウザに保存されます。
2. 画像を撮影/アップロード → OCRで店名・日付・合計が反映 → 必要ならメモ/分類を調整 → 保存。
3. 画像保存が不要ならチェックは外したままでOK（デフォルトOFF）。圧縮保存したい場合のみチェック。
4. CSVでエクスポートしておくと、ブラウザ初期化時でもCSVインポートで復旧できます。
5. 画像容量が気になるときは「画像のみクリーンアップ」で画像だけ削除できます（テキストデータは保持）。

## パスや設定が変わる場所
- 公開パス: `vite.config.ts` の `base` / `manifest.start_url`
- favicon / アイコン: `public/turtle_icon_receipt.png` を使用
